# design｜可软链接安装的创作技能包

**技能名：`coagentdraw-design`。** 整个本目录就是技能包，通过[SKILL.md](<SKILL.md>)暴露触发条件、阅读路由、模板执行规则和交付前核对。规范与阶段手册是流程的唯一内容源，创作资料留在项目内。

## 安装

在工具仓库根执行：

```bash
bash design/scripts/install_skill.sh
```

默认创建：

```text
~/.agents/skills/coagentdraw-design -> <本工具仓库>/design
```

也可明确指定其他宿主的技能目录：

```bash
bash design/scripts/install_skill.sh /明确的/skills目录
```

[安装脚本](<scripts/install_skill.sh>)只建立目录和这一条软链接；同目标重复执行为空操作，遇到其他同名文件、目录或错误／失效链接会拒绝覆盖，不执行删除或强制替换。它不安装 Krita 插件、不修改宿主配置、不重启服务、不读取或上传作品。

软链接始终引用当前检出目录，更新文档无需同步副本；移动仓库后需人工检查旧链接并重新安装。宿主必须支持技能目录发现和符号链接；不能保证所有智能体自动启用或热刷新。必要时重新扫描技能或开启新会话。

## 加载与执行

1. 用户要求人物形象、角色设计、意图卡、任一八阶段创作或调整这些流程时，先加载 `coagentdraw-design`。
2. 首次创作任务读取[正式执行规范](<Krita中枢创作流程_正式执行规范.md>)与[手册导航](<执行手册/README.md>)，再打开当前阶段正文；其余手册按阶段读取。
3. 用户指定模板或附件时实际阅读原件，沿用所选表格结构与填写提示；少写是缩短内容，不是删字段或替换模板。
4. 用户校准重点时保留交付结构；用户限制范围时不擅自扩成环境、场景、小说或后续阶段。资料事实不能捏造，但受委托设计时应提出标为未定稿的具体外观方向，而不是把所有未知推回给作者。
5. [角色意图卡](<执行手册/01_文本创作起点.md>)采用视觉设计版，只保留“作者要求与设计锚点、可见形象”两部分；角色标识填名字或代号，设计目的写用途与预期效果，核心幻想与表现风格的提示简短直接。当前锚点可直接进入02按需找角色和资料，先用 Web 图库广泛预览、标注与筛选，方向较明确后将选中素材带入04试拼；完整卡仍保留具体整身粗方案。主形与辅形的方向、比例和分布用于试拼中的分析调整，再细化依附结构；主体改变时重看依附设计。外观先整体后局部，“视觉重心”记录服装大形、身体比例、关键装备、发廓与主色块组成的核心识别组合。外观分别填写已有条件与探索方向；仅按这两部分交付，来源在对应格内短链接。
6. [04 角色视觉探索](<执行手册/04_角色视觉探索.md>)支持先用AI生成或绘制服装／核心物件设计草案，比较修改后与整身试装往返；可以先设计全部所需部件，但不要求全部先定稿。部件草案、实际试装与角色主稿分别判断，生成设定板的多视图和文字须核对，不代替06三视图。
7. 自检模板完整、范围一致、事实／建议分明后交付；不把文件、登记事件或工具执行数量当成果。

技能加载失败时，直接读[技能入口](<SKILL.md>)及对应手册。跨仓库调用也应遵守工具仓库的[协作规范](<../AGENTS.md>)；先解析技能真实路径再定位工具仓库，不假定技能挂载目录或当前工作目录就是源码目录。

## Web 资料预览的加载入口

搜索角色、收集风格或服装参考、整理逐图标注、建立本地图库时，加载本技能并读[02](<执行手册/02_联想与前期调研.md>)与[参考图库工具说明](<../docs/tools/references.md>)；进入拼贴时再读04。早期资料用项目内图片和 `references.json` 组织，通用网页负责展示。方向较明确后，将选中原图或独立裁片交给 Krita，原始资料继续保留。

维护职责：本页说明安装与加载；技能入口决定何时读哪份手册；总纲规定成果和交接；02规定检索、标注与选择；工具说明维护命令及数据格式。调整流程时检查这些入口是否一致，真实项目的素材清单不写入技能包。

## 目录职责与权威

| 内容 | 职责 |
|---|---|
| [技能入口](<SKILL.md>) | 模型触发、按需加载、模板执行与自检；不另定一套创作流程 |
| [正式执行规范](<Krita中枢创作流程_正式执行规范.md>) | 唯一现行创作总纲，决定阶段、成果与安全边界 |
| [八阶段手册](<执行手册/README.md>) | 各阶段具体动作、原表格和交接条件 |
| [调研报告](<调研报告/README.md>) | 按问题使用的参考与来源，不覆盖作者决定和现行规范 |
| [项目状态 CLI](<项目状态_CLI.md>) | 使用登记与版本功能时再读；状态不等于艺术验收 |
| [参考图库](<../docs/tools/references.md>) | 外部 JSON 逐图标注、本地 Web 预览及选中素材交接 |
| [工具能力与验证](<工具能力与验证.md>) | 工程和验证边界，不当作绘画已完成的证据 |

仅将通用方法和规则放在技能中。真实人物资料、填好的意图卡、参考原图、生成候选及可编辑源继续留在项目内，不因安装技能而进入公共文档。

## 离线验证

在仓库根执行：

```bash
python3 -m unittest discover -s tests -p test_design_skill.py -v
bash -n design/scripts/install_skill.sh
git diff --check
```

检查清单元数据、八阶段路由、文档链接及软链接安装的幂等／冲突保护。它们不能证明模型必定遵循指令，也不能代替宿主实际加载、Krita 实机或作者艺术验收。

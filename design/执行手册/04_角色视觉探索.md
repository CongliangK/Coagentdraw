# 阶段4｜角色视觉探索

> 现行手册；稳定 ID：`character_exploration`。工具能力见[能力说明](<../工具能力与验证.md>)；共用规则见[手册导航](<README.md>)。

围绕已定角色与当前锚点，把02的外部参考转为**本角色的服装／核心物件设计草案 → 比较与修改 → 整身试装／拼贴 → 结构线稿与基础色**。部件草案本身就是视觉设计成果，不必等完整人物立绘出现才开始设计；也不能把外部参考直接当作本角色的部件定稿。

这是阶段四内部可往返的工作方式，不新增宏观阶段或逐轮审批。可以先设计所需的全部服装和核心物件，再组合；也可以先做一部分、试装后继续补设计。**不要求所有部件先定稿才能试装。** 已有可用部件或整身原型时直接从当前问题继续，不重复起步。本流程的实际收益仍待真实作品验证。

## 起步：明确整体约束与本轮部件

1. 承接01的设计锚点、03的主线和02的资料与尝试记录，简记当前要保持的身体比例、风格、核心识别组合及本轮比较问题。不要求补齐整卡或先画独立剪影。
2. 从整身需求挑本轮值得设计的服装或物件，例如外衣、内装、包袋、鞋靴、武器、头饰、扣具；不是逐项必须完成的清单，不预设数量。先明确类别、体量、穿戴位置和用途，再展开依附结构及细节。
3. 穿戴与随身物件先看怎样出现在人物身上：谁承重、怎样固定、如何拿取、与衣服怎样遮挡；区分可见携挂与包内收纳。装饰可以只服务审美，不强迫全部参与战斗；只有任务涉及变形或组合时再研究对应机制。不把单个项目的装备和模式推广为通用要求。
4. 在项目内打开或按需建立 Krita 角色设计稿。部件草案可放在同一文档的探索组／区域，需要独立编辑时也可另存文档，记录路径与版本即可；不强制另建资料板或一套空文件。

### 底稿与操作分工

- **已有角色稿：** 保留当前有效主稿分支；在探索组设计、导入和试装部件，沿用既定比例与画幅。
- **尚无身体底稿：** 可以先做服装平铺图、物件独立图或局部设计；不因此阻断部件探索。整身试装前再采用作者提供或已允许使用、视角适配的比例底稿；没有现成底稿时，由具备实际能力的执行者用参考辅助的粗人形／简单块面建立基底。未放上身体不能声称整身协调已验证。
- **资料或草案可用但无法拆件／变形：** 给出目标部位、版本、拟调整的大小与方向，明确缺的是选区、裁切还是变形；由具备能力且获授权的执行者接续，或回搜更适配的材料。并置不是贴合试装，不把操作缺口一概交给作者“手工润色”。

AI可以承担草案生成和绘制，不要求作者先会精细手绘。生成前核实本次任务授权、可用模型与输入方式；云端发送项目资料须另有明确授权。不为起步前置新模型、Blender或新控制管线。实际执行者负责非破坏编辑、绘制与保存，作者负责表达、比较和取舍，不新增逐步审批。

## 一、设计服装与核心物件草案

**输入是当前设计问题＋选中参考，不是将已有角色零件直接据为己有。** 参考来源保留，明确借用的形体关系及要重新设计的部分。需要新资料时回02，不用生成图充当现实或来源证据。

以真实图像呈现可讨论的方案，可以由AI生成、绘制或参考辅助重构。根据本轮问题选用以下内容，不要求每件都出完整设定板：

- **主体外形：** 服装平铺／穿戴粗图、物件独立图，明确类别、长短、体量与大形。
- **必要视角：** 正侧背、局部或剖示只补解决问题所需的部分；未画出的面标未知。部件多视图不替代06的同一角色正侧背设定。
- **连接与使用：** 开口、扣合、背带、承重、握持、可拆部位与收纳位置；涉及变形时展示关键状态及构件去向。
- **配色与材质：** 可在草案阶段做色块变体、软硬与表面表现的比较，不必等整身清线；材质图和文字只表达意向，不证明真实功能。

候选围绕有意义的差异展开，不设固定配额。可以暂用简化人形或不画脸；不能用精美版式、密集标签和装饰细节掩盖主体设计缺失。图上的必要说明由助手核对后另加简短可读注释，不依赖模型生成文字的准确性。

**生成设定板先当候选：** 逐视角检查同件物品的数量、轮廓、左右、连接与开口是否一致；图面标注与实际画面是否相符。发现矛盾时实际修改、重新生成或明确留缺口，不能只因“正侧背都有”就认定结构成立。生成整张PNG不等于得到了透明拆件、可编辑线稿或语义分层。

## 二、比较、挑选与修改部件

在相近尺度、视角和完成度下比较：该部件的形体、用途与角色气质是否成立，是否值得放回整身；颜色、材质、连接分别比较，不因某案完成度高就优先。由作者保留、调整、拆合或暂存，未选原稿保留。

部件内部的主体构成先行，依附件与纹样后置；同时保留整身比例和风格约束。可先比较部件再组成整身，但精细连接和装饰不应在试装前全部锁死。只有看图仍无法判断的关系才继续补图，不以文字候选清单代替设计草案。

## 三、整身试装／拼贴与协调性验证

早期外部资料继续留在 Web 图库；仅把选中的参考、本角色部件草案或非破坏裁片带入当前 Krita 工作画布。参考旁置，试装部件进入探索层／组，与身体底稿、原稿、候选分开；作者接受并实际采用后才变更当前基底，输出隔离参考。沿用既定画幅，旁置空间和导出规则见[工作画布组织](<../Krita中枢创作流程_正式执行规范.md#工作画布与文档组织>)。

1. 保留原图，按实际能力拆件、移动、缩放、旋转或变形；关键衣物与物件能独立移动、隐藏和调整。单张设定板不能直接假称为可拆部件，须实际取得适配裁片或重绘；不相容视角不能靠强行拉伸掩盖。
2. 回到全身看身体、服装、包袋和装备的体量、比例、重心、轮廓、负形与色块。形状语言用于分析主形和辅形的方向、比例与分布，不把抽象几何或独立剪影变成前置门槛。
3. 检查穿戴与代表动作：背带从哪里经过，衣物和挂件谁遮住谁，工具怎样抽取，手臂与腿能否活动。涉及不同状态时比较轮廓和空间分配，不默认每个部件同时展开。未测的承重、容积或动作留作未解处。
4. 由作者决定保留、调整或放弃；理由落在图上，如包体过重、遮住主色块、武器与手不匹配、挂件与衣摆冲突。部件自身有问题回部件设计，整体方向有问题回03，参考不适配回02。

**部件设计 ↔ 整身试装反复往返。** 单件好看不等于组合成立；整体或主体改变时重看依附设计。可直接试拼外部参考检验大型，再回到部件草案重构；不必为了符合顺序重做已有有效探索。试拼粗糙可以，未导入、未贴合、未试动作不能登记成已验证。

## 四、重构结构线稿与基础色

成立后带走的是比例、轮廓、服装／装备关系等设计决定，不是来源角色的标志性轮廓与纹理。依据部件草案和整身原型重构本角色的结构线稿，重新解决连接、厚度、遮挡、裁片、缺失面和细节；软布垂落、硬件支撑、穿脱开口与固定位置须说得清。边缘检测、描边、滤镜或换纹样不等于原创结构再造，AI生成也不自动保证原创或发布权利。

结构基本可读后，用独立基础色层整合颜色分区、面积和主次，继承或修正部件试色，在预期背景下观察整身。来源原色与草案试色都不自动锁定，不强制厚涂。线稿与基础色须能继续分别修改，需独立调整的部件应有实际有效层／蒙版；不能以被不透明成图盖住的旧层冒充有效分层。04已形成的结构线稿和色彩直接交05继续收敛，不各重画一次。

### 简短示例：先设计旅行包，再试装

以下仅为通用教学假设，无对应作品或作者决定。要比较“扁宽挎包”与“窄高挎包”，先依据当前锚点与02参考，形成两种本角色包体草案，画清包盖、背带接点和外挂位置；只补需要的侧视与色块，不先精修每条缝线。

把选中包体实际放在统一身体基准上，检查披衣遮挡、髋部体量、手臂摆动和取物。若扁宽包压住主体色块，回改包体比例、位置或背带，而不是只添纹样。结构成立后再整合线稿与基础色。尚未贴合角色的独立包图只能称为部件草案，不能称为整身试装成果。

## 记录与交接

沿用02同一条“尝试与反馈”，串起参考ID、部件候选版本、试装位置、反馈与决定，不为每件物品另抄素材表；本角色草案与外部来源分别标明。以下原阶段短表只记录本轮变化，引用已有图像，不新增逐轮审批表。

| 项目 | 填写提示 | 填写内容 |
|---|---|---|
| 本轮要看清什么 | 当前角色、锚点、保持项和比较问题；引用02同一尝试 | |
| 部件草案 | 服装／核心物件候选在哪个文档、组或图像版本？哪些是本角色设计，哪些仍是外部参考？ | |
| 部件比较与修改 | 保留、调整或拆合了什么？连接、视角一致性与使用方式还有哪些缺口？ | |
| 剪影/大形 | 记录真实试装位置与版本：身体、衣物、道具是否协调？轮廓检查发现什么？ | |
| 粗线稿/穿戴 | 哪些结构已重新设计，哪些仍只是临时素材？ | |
| 结构与动作 | 谁压住谁、怎样固定、怎样活动？缺失面和不适配视角是否已处理？ | |
| 平涂配色 | 部件试色与整身基础色分别到哪一步？颜色在哪里、占多少；未做标未做 | |
| 对比观察 | 同尺度看部件、全身与必要局部，指出作用和代价；决定写回02尝试与反馈 | |
| 下一步 | 回改部件、继续试装、回搜资料、重构结构还是交05收敛？ | |

**完成与交接：** 能指出本角色部件草案、真实整身原型与探索图的关系、差异和代价，有可供收敛的方向。按任务需要保留部件设计与比较，不强求全部物件独立成板；只做部件时如实交付部件探索，不冒称完整阶段完成。交 [05](<05_角色方案收敛.md>) 须说清部件草案、整身试装、结构线稿、基础色各自到哪一步，以及未解连接／动作问题。独立部件板或拼贴原型都不能替代05的原创清晰主稿，部件正侧背不能替代06。

选区、变形、液化和笔刷等操作由具备相应能力且获授权的执行者完成；当前插件没有通用笔刷／变形／滤镜接口，也不提供从生成设定板自动拆件和验证结构的能力。能力不足就保留输入和具体缺口，不用空层、脚本成功或生成占位图冒充实际试装。共用非破坏、目标核对和安全回填规则继续适用。

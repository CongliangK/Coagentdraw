# Krita 中枢创作流程｜正式执行规范

> 现行唯一总纲 · workflow 目标 `krita-character-illustration-v1`。依据用户确认的 U 决策及《Krita 中枢改造规范 v1.0》的 E 实施规则；V 能力仍须实测。本页确定创作合同，不宣称程序已完成迁移。旧审核初稿和研究案例仅供历史追溯。

## 主线与判断权

Krita 是观看、比较、修改和保存的视觉中枢；浏览器访问资料、ComfyUI 计算图像、CLI 调度，均不能替代视觉现场。作者可以主要观看、圈示、文字表达和选择，AI 可以承担绘制，不以高质量手绘底稿为入场条件。Markdown/JSON 只负责轻量文字、来源与机器索引。

**大量文本起点 ↔ 图文联想调研 → 跨创意比较取舍 → 剪影/服装/线稿/配色共同探索 → 角色方案收敛 → 正侧背三视图 → 独立插画方案探索确认 → 分工序制作交付。**

创意选择、角色确认、插画确认是三次不同判断。数量丰富指不同可能性，不预设只能两三个；可回退、拆分、合并或只做一段，但不能把缺必需成果的路线标成完整完成。具体角色、尺寸、画风与用途由作者指定，不虚构用户作品或确认。

| 阶段 / 稳定 ID | 必需成果 | 日常手册 |
|---|---|---|
| 01 文本创作起点 / `text_seeds` | 可持续累积的多个文本起点 | [执行](<执行手册/01_文本创作起点.md>) |
| 02 联想与前期调研 / `research_imagination` | Krita 素材簇、初步意象及必要来源 | [执行](<执行手册/02_联想与前期调研.md>) |
| 03 创意汇总与选择 / `concept_selection` | 跨起点创意取舍与本轮主线，未选保留 | [执行](<执行手册/03_创意汇总与选择.md>) |
| 04 角色视觉探索 / `character_exploration` | 真实剪影、服装组合、粗线稿、动作和平涂试验 | [执行](<执行手册/04_角色视觉探索.md>) |
| 05 角色方案收敛 / `character_resolution` | 清晰主视图线稿、基础色、保持项与实际修订 | [执行](<执行手册/05_角色方案收敛.md>) |

## 四类工作文档（按需建立，不初始化空 KRA）

| 文档角色 | 本地默认路径示意 | 视觉组织 |
|---|---|---|
| 想象与提案板，02—03承接01 | `documents/ideation/board-001.kra` | 阅读说明、素材簇（每图独立）、短注/草图、待比较、本轮选中、未选暂存 |
| 角色设计稿，04—05 | `documents/character/<concept_id>/design-001.kra` | 意图/保持项、参考、探索、主稿（线稿/基础色/局部说明）、修改候选、诊断 |
| 三视图设定，06 | `documents/turnaround/<concept_id>/sheet-001.kra` | 说明/基准、正面、侧面（角色自身左/右）、背面，各自线稿/基础色，局部、旧版本 |
| 插画稿，07—08 | `documents/illustration/<illustration_id>/painting-001.kra` | 角色参考/意图、构图候选、确认稿、制作、AI候选、诊断 |

画幅由任务确定；资料多就分批分页，不把单板无限扩张或取消资源限制当作海量支持。默认共享视觉载体是普通层/组；原生 Reference Images 允许人工辅助，但不假定插件可控制或 AI 采样已包含画布外对象。名称不等于身份，绑定丢失/多义须重新核对。

## 人与 AI 的工作合同（E01—E10）

观察 Krita 问题 → 确认目标 → 执行/准备候选 → 回到 Krita → 同尺度全图/局部比较 → 作者接受、拒绝或继续改 → 授权保存。

- 图像引用须定位文档、KRA、组/层或整文档像素区域及版本预览；屏幕坐标不能当画布像素。参考、候选、主稿、诊断分开，采样/导出声明范围，不临时隐藏作者层后猜恢复。
- KRA 是可编辑源，PNG 是派生物；位图可编辑不等于自动语义分层。需要线稿/基础色独立就真实保留。工作文件可变，批准快照不可覆盖；批准关联对象、版本/摘要、范围、时间和真实指令来源，不能让模型自报 human。
- 新 AI 结果先候选，不自动覆盖主稿。overlay 只叠加；replacement 必须能消除旧形且保留源分支。不能安全替换时独立候选文档比较，明确“合成位图候选”限制。预览结束恢复前态需检测人工可见性冲突。
- 模型执行成功、已导入、作者选中、实际切换显示、阶段完成是不同事件。偏好只在相关创意/角色/本轮范围生效，不把所有拒绝史塞进全局禁令。诊断与 AI 自评不替代作者艺术判断。
- 写入必须核对目标身份、源内容、尺寸、区域/选区与映射；无选区不默认为整图。源变、重开或目标不明只保留候选。操作 ID、收据与同次服务端主线程条件检查是后续工程要求；客户端先查再写不等于安全回填。超时/取消未知先查询，不盲重试；保留 RGBA/U8/ICC、主线程和本地监听守卫。
- 只有普通编辑参考图输入不能冒称 Mask 原生采样或 Lineart/Depth/Pose 专门结构控制。受控区域合成须与原生 Mask 分开描述。能力失败据实报告并保留可操作视觉路径，不退回仅输出说明冒充完成。Depth/Pose、特定超分与频率分离可选，不前置 Blender 或大型 Web 工作台。
- 来源保留作者/机构、标题、本地原图位置、网址和已知限制；未知明确未知，书页区分 PDF 页序、印刷页和图号。观察、联想、事实与推断分开；第三方参考默认本地，不上传 KRA、原始资料、权重和密钥。机器尽量自动记录，不让作者重复抄三套表。

## 新旧语义与迁移边界

PR-01仅文档；PR-02已实现离线schema2 + workflow索引和按文档角色的新预设，schema1仍只读旧语义。新状态含多 `ideas`、`selected_concept_id`、多角色 `documents`、版本化 `assets/decisions`、稳定stage_id与带workflow的历史；current_stage仅关注位置。状态pending/in_progress/awaiting_review/completed，最后一种需成果和可追溯人类来源确认，不能CI自动批准。索引/组层不等于图像链路或艺术验收，实际接口见[项目状态CLI](<项目状态_CLI.md>)。

| 旧语义 | 新语义与人工复核 |
|---|---|
| 01 单意图 | 新01的一条起点，可给新03/05引用，不独占主线 |
| 02 调研 | 新02保留资料并整合联想，不由少量参考自动通过 |
| 03 同角色提案 | 分辨跨创意选择（新03）与视觉变体（新04） |
| 04 探索 | 可引用新04，拼板不等于服装线稿已完成 |
| 05锁定＋06收敛 | 合并新05；旧06 completed 不等于三视图 |
| 07交付 | 设定图引用新06，最终导出服务新08，缺侧背不通过 |
| 08插画 | 按真实成果拆新07/08，不自动双完成 |

PR-02采用保留原文件的显式升级：旧状态按旧规则只读解释、旧sidecar保留旧预设；先生成只读migration-plan，经明确授权、匹配摘要/修订后，不覆盖备份原状态再写新索引，旧资产保持路径与语义，不移动或重命名用户KRA。不确定项待确认，新阶段不自动继承 completed；失败保留原文件和部分结果，不破坏性重置。角色主稿变更使三视图需复核，三视图变更使关联插画需复核；批准不静默套新内容。

旧[审核初稿](<角色设计八阶段工作规范_审核初稿.md>)保留原文；旧手册路径为短迁移入口，正文在[历史档案](<历史/旧八阶段执行手册_基线8c457d35.md>)，01完整意图卡另在新01可展开。用户58b2444阶段二的联想板、多可能、跨领域、自由并置、暂不知吸引力和事实考据区分均整合到新02，而不盲合旧分支。

## 验收与执行顺序

A 离线检查、B Krita/ComfyUI 实机、C 真实创作艺术验收分别记录。PR-01 文档完成不等于系统完成；空表、prepared payload、三图存在、导出包存在都不能代替真实画面与作者确认。源文件需保存重开，导出无参考/诊断污染，真实试用至少一次可见修订。

按 PR-01 文档 → PR-02 版本化状态 → PR-03 资料/创意入画布（即含目标写入保护）→ PR-04 线稿平涂/安全修改 → PR-05 三视图/插画确认 → PR-06 制作/交付实施。每段提交的工程、联调、艺术结论分开；既有 Issues 不因文档更新关闭，#17/#25仍需真实闭环、#27专门结构控制仍待验证、#29保持可选。详见[需求与证据跟踪](<Krita中枢改造跟踪.md>)和[项目状态 CLI](<项目状态_CLI.md>)。

优先级：最新明确用户指令 > U 决策 > E 实施规则 > 新手册 > 历史规范/案例。研究只作为依据，不宣称普遍行业标准；未经核查不升级历史来源可信度。

# Krita 中枢创作流程｜正式执行规范

> 现行创作总纲 · workflow `krita-character-illustration-v1`。工具实现与验证边界见[工具能力](<工具能力与验证.md>)。

## 主线与判断权

Web 图库是早期资料的观看、标注与筛选入口；Krita 是试拼、绘制、修改和保存的视觉中枢。两者按当前问题分工，ComfyUI 计算和 CLI 调度不能替代真实图像成果。作者可以主要观看、圈示、文字表达和选择，AI 可以承担绘制，不以高质量手绘底稿为入场条件。Markdown/JSON 只负责轻量文字、来源与机器索引。

**角色设计默认试点：当前设计锚点 → 通用搜索找角色 → 按优先级找对应三视图/设定资料 → 本地 Web 图库广泛预览与标注 → 方向较明确后将选中素材导入当前画布试拼大型与协调性 → 保留、调整或放弃 → 重构原创线稿 → 上色 → 本角色正侧背设定核对。**

这是仍待真实创作验证的流程假设，不宣称行业已证明或工具已实现。没有明确锚点时，仍可从文本起点与开放联想找到方向；已有角色与明确主线可直接进入相应环节，不强迫重填整卡、另造人物或先无参考手画剪影。阶段编号是成果组织，不是每轮重新排队的审批链。独立插画按07/08推进，由实际任务决定是否继续。

**核心幻想是角色设计的中心：角色要为观众、玩家或读者提供怎样的幻想与想象。** 它不只是角色的性格、反差或泛泛的“吸引力”；意图卡须明确保留“核心幻想”字段，后续创意选择与视觉探索围绕它展开，不把关键词简化掉。

**形状语言用于试拼中的分析与调整。** 从具体锚点和图像出发，观察圆、三角、方形等主形与辅形的方向、比例、分布和轮廓节奏，讨论身体、服装及装备如何共同构成整身大形。整身剪影与主体构成 → 依附结构 → 表面细节仍是结构依赖；主体改变时重看依附设计。剪影是轮廓检查手段，不是拼贴前必须独立完成的作品；不要求先定完抽象几何或全部外观。情绪倾向结合重心、曲直与语境判断。

**核心视觉组合共同承担角色识别。** 意图卡的“视觉重心”写出服装大形、身体比例、关键装备、发廓与主色块如何组合；统一的是核心命题，具体核心要素可以多项协同。先确定这组可辨认的构成，再安排次要支撑与表面细节。画面视线落点属于呈现设计，与角色的核心识别组合分别处理。

创意选择、角色确认、插画确认是三次不同判断。数量丰富指不同可能性，不预设只能两三个；可回退、拆分、合并或只做一段，但不能把缺必需成果的路线标成完整完成。具体角色、尺寸、画风与用途由作者指定，不虚构用户作品或确认。

## 角色设计试点的最小工作闭环

- **输入只需当前问题。** 例如想试披风或大锤；性别仅在已知且相关时附加，未指定即不限。不强制先填满风格、世界观或配色等搜索约束；已有明确要求仍须保留。
- **先找角色，再找资料。** 用通用搜索发现符合锚点的角色并说明优先理由，再逐个查找对应三视图，核看原页面与图像。角色名命中不等于素材可用；视角、姿态、透视、遮挡与部位结构须适合当前试拼。三视图优先；资料不足的退路见 [02](<执行手册/02_联想与前期调研.md>)。不建设巨型素材库作为前置。
- **先在 Web 图库广泛比较。** 项目内原图配独立 `references.json`，每图记录设计意义、来源、作者/机构、使用限制及标签，工具测量宽高、长宽比、透明度与摘要。通用网页读取外部数据集，见[参考图库](<../docs/tools/references.md>)；不把全部图片提前导入 Krita。方向较明确后，仅把选中素材带入当前画布。
- **先试大型，再决定怎么画。** 在当前角色画布中拆件、移动、缩放、旋转或变形，观察全身比例、负形、体量与协调性，由作者保留、调整或放弃；失败反馈带回下一次搜索。操作须有实际能力和相应授权，未取到/未导入/未试拼分别如实记录。
- **原型传递设计决定。** 在原型上重构自己的轮廓、连接、厚度、遮挡和具体细节，形成原创结构线稿，再上基础色；不能描边或滤镜化来源碎片后就宣称再造完成。参考角色三视图是前端材料，本角色正侧背才是 06 的交付物。详见 [04](<执行手册/04_角色视觉探索.md>) / [05](<执行手册/05_角色方案收敛.md>)。
- **记录跟着尝试走。** 复用 02 原短表的“尝试与反馈”一行，用角色/资料、画布版本或失败状态、决定及理由串起一次尝试；04/05只引用同一记录，不另造表单。只保存本轮需要的来源、用途和授权状态，未知标明；不以改造程度作法律保证。

本试点采用“拼贴原型后再绘制”。直接拼贴成品是另一种用途，不在本轮默认交付范围；本页不据此取消其他用途，也不将原型参考自动视为可公开分发素材。能力与验证限制见[工具能力](<工具能力与验证.md>)。

本地材料、裁片、尝试记录和KRA均留在仓库根 `项目/<项目名>/`，沿用[本地项目约定](<../README.md#本地设计项目>)，原有 `_本地暂存/` 不迁移。无底稿/操作能力不足的分支及教学示例见04；直接角色稿与02索引的登记方式见[项目状态CLI](<项目状态_CLI.md#同画布素材的登记>)，不为满足机器索引而补建空板或虚报完成。

## Web 资料与画布的交接约定

通用网页与项目数据分离：原图、逐图设计意义、出处与测量信息保存在项目资料集中，网页读取展示；增补资料更新数据，不为每个项目改 HTML。具体格式和命令由[参考图库说明](<../docs/tools/references.md>)维护，逐图观察与筛选方法见02。

进入试拼的条件是已能指明拟试用资料、目标部位和需要检验的形体关系；无需先敲定全部服装细节。Web 勾选与导出清单表达试用意向，实际导入与试拼反馈另绑定画布层/组和版本。02可交付完整可看的 Web 图库而无 KRA；04的协调性判断仍需真实试拼图。未选材料留在图库，不转成画布负担。

## 07—08 的日常制作组织

| 现行阶段 | 内部工作与交接 | 详细操作唯一入口 |
|---|---|---|
| 07 插画方案探索 | 三轮：表达与构图动作比较 → 结构与空间 → 结构与光色确认稿。确认稿让裁切、人物大小位置、动作接触、遮挡、焦点、明暗与主光冷暖可见，交给 8A/8B | [07 手册](<执行手册/07_插画方案探索.md>) |
| 08 插画制作与交付 | 四轮：整幅底画（8A＋8B）→ 局部与必要细节（8C＋8D）→ 全图统一（8E）→ 按用途收尾交付（8F＋8G）；保留全部 8A—8G | [08 手册](<执行手册/08_插画制作与交付.md>) |

作者持续统筹一张连续发展的主稿，助手围绕当前稿和短问题协助绘制、比较；轮次可以合并或往返，不新增宏观阶段、候选配额或逐轮审批。本幅表达任务可以是事件、状态、情绪、关系或形象气质；三视图约束身份和关键结构，不唯一决定镜头、动作、空间与观看顺序，也不要求逐项展示装备。

确认稿记录当前制作决定，不冻结全部像素。每次候选先看具体问题，再回全图核对，作者接受并实际采用后才成为下一轮基底；相互影响的局部不在过时底画上各自完成后强拼。表达或大结构有问题回 07，局部、统一或尺寸有问题回 08；生成改身份先修当前插画，只有原设定自身矛盾才回 05/06。具体任务、失败出口、回退与完成判断以两份手册为准。

## 工作画布与文档组织

**进入试拼后，当前工作画布承载绘制与选中素材。** 早期资料留在 Web 图库，方向较明确后只将拟试用的素材导入。草图、当前绘制/编辑结果和这些选中素材放在同一Krita工作文档中；素材在绘制区域旁可见，按来源保留独立层/组，便于随时对照、取部件拼贴。草图、原稿与编辑候选分层保留，可并排或切换比较；作者接受并实际采用后才替换当前工作基底。素材旁置区不属于作品最终输出，导出须明确作品区域或在副本中隔离参考。已有画幅不擅自扩缩，空间不足先利用现有空白或观察副本，再按作者需要调整工作空间；不为放素材缩小源稿。

四类文档按需要选用，不强制将素材板与角色稿拆开。

| 文档角色 | 本地默认路径示意 | 视觉组织 |
|---|---|---|
| 想象与提案板，02—03承接01 | `documents/ideation/board-001.kra` | 阅读说明、素材簇（每图独立）、短注/草图、待比较、本轮选中、未选暂存 |
| 角色设计稿，02素材与04—05 | `documents/character/<concept_id>/design-001.kra` | 意图/保持项、参考、探索（本轮拼贴原型）、主稿（线稿/基础色/局部说明）、修改候选、诊断 |
| 三视图设定，06 | `documents/turnaround/<concept_id>/sheet-001.kra` | 说明/基准、正面、侧面（角色自身左/右）、背面，各自线稿/基础色，局部、旧版本 |
| 插画稿，07—08 | `documents/illustration/<illustration_id>/painting-001.kra` | 角色参考/意图、构图候选、确认稿、制作、AI候选、诊断 |

沿用作者既定画幅、像素尺寸与比例；缩小比较只用显示缩放或观察副本，不擅自缩小源 KRA 或交付尺寸。角色三视图源文件与旧稿分支保留，插画按当前镜头另有结构与制作依据。大量早期资料由 Web 图库浏览、筛选；画布只承载当前要试的素材，不把单板无限扩张或取消资源限制当作海量支持。默认共享视觉载体是普通层/组；原生 Reference Images 允许人工辅助，但不假定插件可控制或 AI 采样已包含画布外对象。名称不等于身份，绑定丢失/多义须重新核对。

## 人与 AI 的工作合同

观察 Krita 问题 → 确认目标 → 执行/准备候选 → 回到 Krita → 同尺度全图/局部比较 → 作者接受、拒绝或继续改 → 授权保存。

- 图像引用须定位文档、KRA、组/层或整文档像素区域及版本预览；屏幕坐标不能当画布像素。参考、候选、主稿、诊断分开，采样/导出声明范围，不临时隐藏作者层后猜恢复。
- KRA 是可编辑源，PNG 是派生物；位图可编辑不等于自动语义分层。需要独立调整的线稿、基础色、光影或局部须有真正作用于当前画面的层或蒙版；旧线稿/平涂被不透明 AI 成图盖住，不算最终画面的独立编辑能力。按需分区、蒙版、补绘与调整不会自动还原生成图语义分层；不强制所有画风做终稿清线。工作文件可变，批准快照不可覆盖；批准关联对象、版本/摘要、范围、时间和真实指令来源，不能让模型自报 human。
- 新 AI 结果先候选，不自动覆盖主稿。overlay 只叠加；replacement 必须能消除旧形且保留源分支。不能安全替换时独立候选文档比较，明确“合成位图候选”限制。预览结束恢复前态需检测人工可见性冲突。
- 模型执行成功、已导入、作者选中、实际切换显示、阶段完成是不同事件。偏好只在相关创意/角色/本轮范围生效，不把所有拒绝史塞进全局禁令。诊断与 AI 自评不替代作者艺术判断。
- 写入必须核对目标身份、源内容、尺寸、区域/选区与映射；无选区不默认为整图。源变、重开或目标不明只保留候选。操作 ID、收据与同次服务端主线程条件检查是后续工程要求；客户端先查再写不等于安全回填。超时/取消未知先查询，不盲重试；保留 RGBA/U8/ICC、主线程和本地监听守卫。
- 普通 edit 可尝试“场景草稿＋角色参考”，不保证几何锁定；HQ局部编辑交互模板使用“当前底画＋真实蒙版”进行裁切编辑和拼回，没有独立第三路角色参考或专用 Lineart/Depth/Pose 条件，不冒称模型原生 Mask。蒙版外扩/羽化及输入语义见 [ComfyUI 说明](<../comfyui/README.md>)；红圈只是诊断，不能代替真实蒙版或硬空间约束。
- 选区、变形、滤镜、笔刷等 GUI 动作由作者，或具备相应界面能力且获授权的助手执行；当前插件没有通用笔刷/变形/滤镜接口。compare 的接受记录不自动替换主稿，review 没有已验证的实际审评后端，不是自动美术总监。能力不足时明确瓶颈，补参考/结构或由作者决定简化，不以“人工润色”暗含作者已有资深精绘能力，也不以文字冒充画完。不前置 Blender、新控制管线或预防性工程。
- 来源保留作者/机构、标题、本地原图位置、网址和已知限制；未知明确未知，书页区分 PDF 页序、印刷页和图号。观察、联想、事实与推断分开；第三方参考默认本地，不上传 KRA、原始资料、权重和密钥。机器尽量自动记录，不让作者重复抄三套表。

## 项目状态与阶段完成

项目索引使用 schema 2、`krita-character-illustration-v1`，包含 `ideas`、`selected_concept_id`、`documents`、版本化 `assets/decisions` 与稳定 `stage_id`。`current_stage` 仅表示关注位置。状态为 pending/in_progress/awaiting_review/completed，completed 需要必要成果和可追溯的人类确认。角色主稿变更触发三视图与插画复核，三视图变更触发关联插画复核，批准不能静默套用到变更内容。具体命令与限制见[项目状态 CLI](<项目状态_CLI.md>)。

01采用[角色设计意图卡](<执行手册/01_文本创作起点.md>)，包含“作者要求与设计锚点、可见形象”两部分。作者要求集中记录，核心幻想说明一次，设计目的与表现风格分别填写；可见形象分列已有条件和未定稿方向，来源在对应格内短链接。完整卡提出具体方向，当前只有锚点时可先检索试拼，再回填得到的方向。

## 验收与执行顺序

A 离线检查、B Krita/ComfyUI 实机、C 真实创作艺术验收分别记录。空表、prepared payload、三图存在、导出包存在都不能代替真实画面与作者确认。源文件需保存重开并检查编辑层实际作用，查看真实导出无参考/诊断污染；实际展示效果与作品是否完成由作者判断，机械检查不代替审美通过，作者自检/AI 诊断不冒称外部读图验证。真实试用从实际问题留下有意义的修订，不为证据制造无意义改动。

创作方法可按手册执行，软件能力以实际实现和验证为准。索引、组层、prepared payload不能代替图像链路或艺术验收。具体缺口见[工具能力与验证边界](<工具能力与验证.md>)。

执行优先级：最新明确用户指令 > 本总纲 > 阶段手册 > 工具说明。研究作为参考，不覆盖作者决定或现行流程。

## 1. 历史服饰结构

- 明确需求：明代曳撒，需能观察领、腰、下摆、袖的结构，不仅是任何古装人物。
- 搜索页：[Commons 曳撒搜索](https://commons.wikimedia.org/w/index.php?search=%E6%9B%B3%E6%92%92&title=Special%3AMediaSearch&type=image)，实际返回 7 个结果。
- 所选来源页：[Yesa C2A000055N000000000PBK.png](https://commons.wikimedia.org/wiki/File:Yesa_C2A000055N000000000PBK.png)。描述为 Imperial Attendants wearing Yesa robes，作者 Unknown，注明源自故宫藏画。
- 图片 URL：[Commons PNG 原文件](https://upload.wikimedia.org/wikipedia/commons/d/d5/Yesa_C2A000055N000000000PBK.png)。HTTP 200、image/png，下载字节数与本地文件吻合。
- 进一步访问的馆藏页：[故宫《明人畫入蹕圖　卷》](https://digitalarchive.npm.gov.tw/Collection/Detail/1625?dep=P)。页面显示统一编号中畫000055N000000000，与所选图编号一致。
- 来源归属：馆藏页面确认画卷名称与编号；Commons 上传者 ChenDaoIsHere 上传了局部图。**「这些人物穿曳撒」是 Commons 描述，并未由实际访问的馆藏正文确认。** 不把文件名或网页标题当服饰定名和裁剪考据证据。
- 所选图一致性：下载使用所选文件页 Original file 的同一文件路径；不是搜索站缓存图。原文件仅 585×438，原文件不等于高清图，也不等于完整馆藏扫描。
- 视觉核验：使用 image-vision/GLM 对本地图片实际核验，原始结果见[costume_vision.txt](<costume_vision.txt>)。模型识别到束带、领口层次与竖向衣纹，但不能看清分裁线、腰线和褶裥构造，明确认为不足以充当曳撒剪裁结构依据；领型等模型判断仍是图像解释，不替代文化考据。
- 限制：绘画局部只能支持外观探索，不能替代实物、版型图或服饰史材料。
- 复杂度：高。百度/Google 验证码、百科标题歧义/缺页后，转到 Commons 站内搜索，再追馆藏编号。

## 2. 真实物件功能

- 明确需求：传统编织背篓，优先希望看到竹编和背负绑带的连接与走向。
- 候选来源：[Back baskets 分类](https://commons.wikimedia.org/wiki/Category:Back_baskets)。实际列出馆藏实物和背负照片，选择其中 Karen 篮筐实物。
- 所选来源页：[Basket, Karen people, Northern Thailand, collected in 1986 - Ethnological Museum, Berlin - DSC01361.JPG](https://commons.wikimedia.org/wiki/File:Basket,_Karen_people,_Northern_Thailand,_collected_in_1986_-_Ethnological_Museum,_Berlin_-_DSC01361.JPG)。
- 图片 URL：[JPEG 原文件](https://upload.wikimedia.org/wikipedia/commons/e/ee/Basket%2C_Karen_people%2C_Northern_Thailand%2C_collected_in_1986_-_Ethnological_Museum%2C_Berlin_-_DSC01361.JPG)。HTTP 200、image/jpeg，3,551×4,614，与文件页的原图尺寸一致。
- 来源归属：Daderot 自摄，页面说明为柏林民族学博物馆展品，拍摄日期 2014-11-11，CC0。族群与地区来自文件页标签/名称，未另行查馆方实物编号。它不是已确认的中国传统竹编背篓。
- 所选图一致性：直接下载文件页 Original file，文件名、类型与尺寸一致。
- 视觉核验：image-vision/GLM 实际读取本地图。实物编织与绳索可见，但仅凭这张图不能完整确定绑带背负方式，也不能确证竹材。详见[basket_vision_complete.txt](<basket_vision_complete.txt>)。
- 清晰度：原图高分辨率，编织纹理与绳索细节有参考价值；功能信息不足不是像素不足，而是缺少佩戴场景与另一侧视角。
- 复杂度：中。分类页 → 文件页 → 原图能完成，精确功能需求还需要另一视角/佩戴照，故记部分成功。

## 3. 艺术风格参考

- 明确需求：指定梵高 1889 年《星月夜》，看旋涡天空笔触与蓝黄关系，不是泛泛「梵高风」。
- 导航页：[The Starry Night](https://en.wikipedia.org/wiki/The_Starry_Night)。正文与信息框列明 Vincent van Gogh、1889、MoMA、作品编号 472.1941。
- 所选文件页：[Van Gogh - Starry Night - Google Art Project.jpg](https://commons.wikimedia.org/wiki/File:Van_Gogh_-_Starry_Night_-_Google_Art_Project.jpg)。列作者、收藏地、编号、Google Arts & Culture 来源链接及作品参考资料。
- 图片 URL：[3840px JPEG](https://upload.wikimedia.org/wikipedia/commons/thumb/e/ea/Van_Gogh_-_Starry_Night_-_Google_Art_Project.jpg/3840px-Van_Gogh_-_Starry_Night_-_Google_Art_Project.jpg)。HTTP 200、image/jpeg。
- 原文件区别：页面原文件为44,567×35,291、663.94MB；此次主动选择3840×3041缩略版本，避免下载超大文件。高清参考成功，原图下载未测试。
- 来源归属：作者梵高，作品《星月夜》，图像来源标为 Google Arts & Culture，Commons 以二维公版艺术复制品标注。馆藏链接存在，但此次未进一步访问 MoMA，记录为文件元数据与百科交叉对应。
- 所选图一致性：下载 URL 的文件路径与所选文件一致；分辨率为有意选择的版本，不是误下载500px网页预览。
- 视觉核验：使用 image-vision/GLM 实际读取本地下载图，结果见[art_vision_complete.txt](<art_vision_complete.txt>)。模型核验到左侧柏树、中部旋涡天空、右上新月、下方村庄与教堂，认为构图匹配且完整，旋涡笔触与蓝黄对比清晰。
- 复杂度：低至中。明确作品页 → 文件页 → 选择合理尺寸 → 下载 → 核验。

## 过程失败与工具能力

1. 默认 shell 的 `bu` 不在 PATH，命令未找到（127）；现有 `~/.agents/skills/browser-use/scripts/bu` 可用，未安装任何工具。
2. `bu --doctor` 初始显示 Chrome/daemon 未运行；通过现有 wrapper 启动 managed headless Chrome 后可访问网页、截图、DOM提取。
3. 百度搜索触发旋转验证码，Google 搜索触发异常流量验证码；未尝试绕过，分别保留[百度截图](<01_search.png>)和[Google截图](<02_google.png>)。百度截图已通过 image-vision 确认是验证码。
4. `Yesa` 导向西班牙地名；`Yesa_(clothing)` 和中文曳撒条目不存在。Commons 站内搜索最终有结果，证明搜索词/标题猜测可能失败，但定向站内检索可补救。
5. 共享 managed Chrome 被另一 agent 同时操作时发生当前 tab 混淆，拿到非目标页面。对应截图[03_yesa.png](<03_yesa.png>)和[05_art.png](<05_art.png>)不用于目标来源结论；已提醒主 agent 停止并发驱动同一浏览器。后续各页URL核对一致。
6. 下载在 `bu` 脚本内使用标准库 urllib + 显式 mihomo 代理，把浏览器提取的图片 URL 保存到本目录；网页导航、检索、DOM提取均由 browser-use完成。下载返回200并经本地格式/尺寸核对。
7. 第一次 image-vision 用1000/1300 max-tokens时输出截断，虽退出0仍不足以作完整结果；保留初次输出并以5000 token重跑。不能只凭退出码确认核验正文完整。
8. 本机现有能力：浏览器可访问明确来源、抽取图片链接、区分原文件与缩略版本，标准库可实际下载，Pillow可测文件，image-vision可实际内容核验。**仍需人工/智能体逐项判定语义匹配，不能把「下载成功」等同于「满足具体设计研究需求」。**

本次无安装、无登录付费、无大规模抓取；项目内产出限于本目录的图片、截图、元数据与记录。

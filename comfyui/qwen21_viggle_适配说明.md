# Qwen-Image-2.1 Viggle Turbo 项目适配

## 来源与事实

基线为用户上传的 `▶▷Qwen-image21-图像编辑&生图-Viggle Turb_my.json`，SHA-256：`2a47a20d0795b2a54a4770ac5499c6814ecbb6c3092d3f66160bd916cc58a9e7`。只读附件不修改；项目维护分离的 [编辑 API](<wf_qwen21_edit_api.json>) 和 [文生图 API](<wf_qwen21_t2i_api.json>)。

附件同时包含两个可保存输出分支：

- 文生图：13 UNET → 15 Turbo LoRA → 5 SamplerCustom；7 文本编码，9 空 latent；14 Euler，6 ViggleTurboSigmas；8 解码 → 1 保存。
- 编辑：31 UNET → 48 Turbo LoRA → 41 consistency LoRA → 28 缓存 → 49 SamplerCustom；37 输入 → 39 约1.5MP Lanczos/32倍数缩放 → 29 文本与参考图编码；35 为 false，实际 latent 来自29的输出2；50 Euler、51 ViggleTurboSigmas；27 解码 → 23 false分支 → 17 保存。
- 45 的第二张图片加载没有接入29，**附件实际是单图编辑**，不是有效的多图编辑示例。
- 23 为 false，颜色匹配链20/22/21不决定默认输出。38/34只用于未启用的空latent分支。不能把备用分支当作已生效配置。
- 两个采样器均 CFG=1、add_noise=true；Turbo LoRA强度1；编辑一致性LoRA强度1；sigma字符串相同。

“LoRA解决一致性”“多图弱于单图”“中英文接近、长文本可用”属于用户提供的实测经验/使用要求；本次据此设计默认路径，但不冒充本次消融实验的结论。Turbo LoRA与consistency LoRA用途不同；当前编辑链必需二者，但不保证身份、服装和多视角绝对一致。

## 相对原文件的改动

| 项目 | 项目版处理 |
|---|---|
| 两条输出混合 | 拆为两个明确的 API 文件，避免一次调用误生成两条分支 |
| 模型、LoRA及采样 | 保留实际生效的加载顺序、强度、Euler、CFG与sigma链 |
| 编辑latent | 直接连接编码器输出2到采样器与sigma节点，删除false切换及备用空latent |
| 编辑输入 | 保留1.5MP/32倍数缩放；编码resolution=0；输出跟随缩放后第一图尺寸 |
| 随机种子 | 删除rgthree种子节点，API直接传入noise_seed，默认42，可由CLI覆盖 |
| 文本 | 删除纯文本传递节点，由CLI完整写入编码器prompt；不强制翻译或截短 |
| 文生图尺寸 | 用928×1664显式尺寸替代分辨率选择器，约9:16/1.5MP，并非声称该自定义选择器的精确计算结果 |
| 颜色匹配 | 原本关闭，不纳入项目默认图；不把全局颜色迁移强加给编辑 |
| 双图 | 仅保留CLI原有显式实验入口；单图提交时去掉image_2，保留第一图缩放引用 |
| 缓存 | 编辑保留；文生图按附件不加缓存 |
| 参数 | 不伪造steps/denoise；旧KSampler模板可继续用原契约与快照 |

项目 [客户端](<../core/cwb_comfy.py>) 对已有契约增加显式第一图缩放映射，避免靠节点名推断；沿用非覆盖上传、总超时、不自动重试、完整运行快照与新图层候选机制。嵌套图像集合与附件扁平autogrow写法存在序列化差异，需在目标ComfyUI实际生成中确认兼容性。

## 使用与一致性策略

见 [CLI与依赖说明](<README.md>)。默认从已批准主稿单图编辑，提示词按“修改对象与目标 → 必须保留项 → 风格/线条/配色约束”组织，可使用完整中文长文本。每次结果先候选，不自动晋升主稿；必要时回到同一批准主稿，避免连续编辑累积漂移。三视图须分别生成、人工核对，不将LoRA当作自动批准依据。

保留附件负面词便于对照；其中 `rough sketch` 与项目粗线稿任务可能冲突，不能把忠实保留误解为所有画风的最佳提示。应在有记录的自定义模板中单独调整后对比。

这不是遮罩局部重绘，不保证区域外像素、透明度或原始尺寸不变。缩放结果不能直接按原图像素坐标声称replacement；导入Krita仍为非破坏候选，不改用户原稿。

## 验证边界

- A离线：契约、LoRA链、六节点调度、参数拒绝、单/双图缩放绑定、重放及旧无缩放契约兼容由 [回归测试](<../tests/test_cwb.py>) 覆盖。
- B环境只读：本次通过本机ComfyUI的 `/object_info` 核对节点注册、输入定义与模型/LoRA文件名枚举；不加载权重，不提交GPU任务。不等于模型文件内容已校验或实际执行成功。
- B实机生成待验：新模板真实执行、嵌套autogrow兼容、LoRA叠加运行、显存、尺寸、运行记录重放均需生成验证。
- C创作待验：同seed单图有/无consistency LoRA对比、单/双图对比、中英文同义长提示对比，核对身份/服装/未指定区域保持和目标修改程度；本次未运行，未声称质量已提升。缺少LoRA时应补依赖，不作为日常回退移除它；无LoRA只用于明确标记的消融实验。

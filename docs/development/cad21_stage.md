# CAD-21：八阶段图层组与幂等 setup

> 工作流为 `krita-character-illustration-v1`，sidecar版本2，按文档角色建组。身份、pending与部分失败有离线mock回归；真实保存重开及作品验收待验证。组层组织不代表绘图或阶段完成。

这是确定性的本地 CLI 功能，无新 UI、无模型/云端调用；只消费 [CAD-11 图层组 API](<cad11_layer_groups.md>)。预设与实现位于 [cwb_stage.py](<../../core/cwb_stage.py>)，入口在 [cwb.py](<../../core/cwb.py>)。不写[项目状态](<../../core/cwb_project.py>)，不自动更新阶段完成、批准或selected_concept_id；项目schema和独立sidecar版本不是同一文件。

## 工作流：按工作文档角色（sidecar v2）

```bash
python3 core/cwb.py stage setup 4 --workflow krita-character-illustration-v1 --role character \
  --document /已授权/专用测试.kra --state /已授权/专用测试.cwb-stage.json
# 同一文档阶段05：沿用已有sidecar的workflow/role，不重复建相同组。
python3 core/cwb.py stage setup 5 \
  --document /已授权/专用测试.kra --state /已授权/专用测试.cwb-stage.json
```

首次新建sidecar必须指定 `--role`；workflow固定为现行流程，可省略。已有sidecar省略role则沿用绑定，显式不匹配时拒绝。角色按阶段兼容检查；只建立该类工作文档所需组，不要求一文档八个阶段，也不创建KRA或内容图层。

| role / 阶段 | 顶层组（含子组） |
|---|---|
| ideation / 01—03 | 阅读说明与当前问题、素材簇、待比较创意、本轮选中、暂存与未选 |
| character / 02素材、04—05 | 简要意图与保持要点、参考、探索（拼贴原型/剪影诊断/服装结构/粗线稿/配色）、主稿（线稿/基础色/局部说明）、修改候选、诊断与比较 |
| turnaround / 06 | 说明与基准线、正面/侧面/背面（各线稿/基础色）、局部结构与色板、旧版本与待确认候选 |
| illustration / 07—08 | 角色参考与画面意图、构图候选、确认稿、制作（结构与底画/光影/关键区域/材质细节/全图调整）、AI修改候选、诊断与比较 |

侧面组默认“待确认角色自身左右”，不替作者决定。没有实际图像/作者确认，组存在不等于设定或插画完成。角色组使用持久语义键如 `character/30_主稿/线稿`；显示名仍带独立随机标记，重开、冲突和部分失败规则与下文一致。

### 拼贴原型与现有组层

角色试拼使用 `character` 文档的既有探索组，来源图放参考组；需独立处理的裁片按实际操作加入内容层。“拼贴原型/剪影/服装结构/粗线稿/配色”子组是组织能力，不表示必须先做独立剪影。子组不提供自动拆件或变形能力。

02素材可与04/05共用 `character` 文档和既有参考/探索组，首次可用 `stage setup 2 --role character`。素材和试拼成果分别登记，见[同画布素材的登记](<../../design/项目状态_CLI.md#同画布素材的登记>)。组存在不代表素材已取得或试拼已完成。

实际创建的每个组名附加独立随机标记，例如 `轮廓诊断 [cwb:5d48e297-b125-41c5-b35c-35955ae14610]`。它是可见持久身份标记，不是服务端文档token。仅创建尚未登记的组，不改名、移动、隐藏、重排或接管现有节点。

## 用法

先由用户在 Krita 中打开并保存一个专用 RGBA/U8 `.kra` 文档（不要用当前作品进行首次验收）。活动文件必须与显式 `--document` 完全对应；同一路径同时打开多份会拒绝操作。sidecar 的父目录必须已经存在。

```bash
python3 core/cwb.py stage setup 4 --role character \
  --document /绝对路径/测试.kra \
  --state /绝对路径/测试.cwb-stage.json
# 原样再次运行：created 为 []，没有重复创建。
python3 core/cwb.py stage status --state /绝对路径/测试.cwb-stage.json
```

- `--state` 必填且文件名必须以 `.cwb-stage.json` 结尾；应与作品一起保留/备份。它不是项目状态文件，不使用或覆盖 `project_state.json`。不默认创建任何项目/缓存目录。
- `stage status` 只读离线 sidecar，不访问服务，不断言图层仍然存在。顶层及所有 `stage ... --help` 均不导入执行模块、不访问服务、不创建缓存或字节码目录。
- setup 输出实际 `created` 语义键、重新解析的组 ID、sidecar 路径。已登记且能确认身份的组不会重新创建，即使用户已改名、移出原外组或调整顺序。
- 不会自动保存 `.kra`。setup 后请用户保存再重开；只保存 sidecar 不会把新组写入作品。

## 身份与重开降级

独立 sidecar v2 记录 `sidecar_id`、文档绝对路径、观察到的 `session`（现有 `/ping` 的 pid 与 `/layers` 根 ID）、每个预设语义键的随机 `token`、创建名称、最近节点 ID、`pending/verified` 状态，以及追加的操作事件。

1. 每次执行先重新查询 `/docs`、`/ping`、`/layers`，核对唯一活动路径与树信息，**全量**验证 sidecar 内已登记的组，再计划缺失组。未登记同名节点（包括 paint layer）存在时停止，不自动接管或生成一套同名组；sidecar 丢失但树中还有本功能标记时也停止。
2. 观察到的 pid/root 不变且已登记 ID 仍存在时，用该 ID 保留改名/移组/重排。不把父级、顺序、显示名称作为身份。标记重复，或 ID 与标记指向不同节点，即使原 ID 尚有效也停止。
3. pid/root 改变或旧 ID 不存在时，丢弃旧 ID 作为身份依据，扫描最新树中的**已登记随机标记**。只有唯一且类型为非根 group 的匹配才重新绑定；不凭“剪影”等同名接管。标记保留时可以移动和改名前缀；零匹配、重复标记、错误类型或多个身份指向同一节点均停止，且不创建任何组。
4. 若用户彻底改名删掉标记，在仍可确认的原会话里可继续 setup；重开造成 ID 失效后则**无法可靠恢复，必须停止人工检查**。被删除的已登记组也不会被自动补建，以免接管替代组。不要删除 sidecar 来绕过检查、复制标记到别的组，或凭名称手改 ID。

**边界：阶段组织读取的 `/docs`、`/layers` 不含文档实例 token，也未接入 `/doc/snapshot` 的会话 token。pid/root 仅为观察上下文，不构成强身份保证。无法检测关闭重开后恰好全部 ID、pid/root 被保留/复用的情况；本项不宣称无条件重开保证。** 可见标记只用于诚实本地工作流，不提供防伪或恶意篡改隔离。另存/移动作品后的绝对路径不会自动迁移；应保留原 sidecar 与作品，人工核对后再做迁移，不另建 sidecar 盲目接管。

## 并发与非原子失败

- 单个 sidecar 使用 POSIX 非阻塞独占文件锁；锁文件永久保留，不能删除/替换。JSON 经同目录临时文件、fsync、原子替换写入，替换前核对原始字节，拒绝已变化/损坏/未知版本/符号链接状态。首版针对本地 POSIX 文件系统，不保证同步盘/网络盘语义。
- 锁只协调同一 sidecar 的调用；运行期间**不要切换/关闭文档、手工编辑图层或同时使用其他写入者**。每个写请求前后再次查询路径与观察会话，但已有 API 没有原子的 expected-document 参数，查询与 POST 之间仍存在切换竞争窗口；这不是文档锁，也没有跨 HTTP 原子事务。若需要严格并发文档隔离，必须等后续强身份/条件写入契约，不能声称本项已经提供。
- 每次写请求前持久化 `pending`：操作 UUID、语义组键（若有）、准确请求 payload、随机标记。响应到达先记录，再回读当前树校验新 ID、类型、名字、父级、并确认 ID 之前不存在。只有通过才记为 verified 并清除 pending。
- 超时、HTTP 错误、回读不符/失败、用户中断或结果日志落盘失败都可能已经留下部分组。保留发送前 intent、已收到的响应与故障；可用时另存失败时树快照，读不到则记录回读失败。**不自动回滚或删除，不声称所有阶段组一起成功。** 后续遇 pending 一律停止，不根据“树里看起来有了”自动认成功，也不重发可能仍在运行的请求。
- 处理 pending：先停止所有写入者，使用 `stage status` 和 `layers` 留证，确认服务端请求已终结并在专用文件核对实际树。保留原 sidecar/作品备份；本最小版不提供自动修复/接管命令。需人工审核 ID、随机标记、类型、挂载、PNG 像素等后按记录契约恢复，不能只清空 pending 就重跑。若无法可靠确认，保持停止并报告边界。

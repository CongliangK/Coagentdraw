创作方法以[正式执行规范](<Krita中枢创作流程_正式执行规范.md>)和[阶段手册](<执行手册/README.md>)为准。本页仅说明当前实现与缺口，不记录流程沿革。

| 模块 | 当前提供 | 尚未完成或验证 |
|---|---|---|
| 项目状态 | schema 2 / `krita-character-illustration-v1`；多起点、选择、多文档、版本化资产、带来源的人工决定及批准失效 | 只核对本地索引/文件；不验证画面、KRA内部编辑能力或人类身份 |
| 阶段组 | sidecar 2；按 ideation / character / turnaround / illustration 建组，标记重解析、冲突与部分失败保护 | 真实 Krita 保存重开未验；空组不等于创作成果 |
| 资料检索 | 本地已有 JSON 的关键词检索、精确定位与采用记录 | 不自动在线找角色、下载图片或解析 PDF |

## 同画布素材与作品

早期资料先在 Web 图库浏览与筛选；进入试拼后，选中素材、草图和当前绘制/编辑结果在同一工作画布组织，素材旁置并独立分层。`character`文档支持02素材和04—05创作登记；02成果可为 `research_materials` 或独立板的 `research_board`。详见[登记方式](<项目状态_CLI.md#同画布素材的登记>)。Web 图库也可用独立完整数据集快照与网页截图登记 `research_gallery`，无需创建KRA。以上是资料预览、索引与组层能力，不是自动摆图、拆件、编辑或作品区域自动导出。

## 验证职责

- **A 离线**：测试、语法、契约和文档链接；不等于真实 Qt/Krita 或 GPU 执行。
- **B 实机**：专用测试文档、真实模型输入输出、有效编辑层、保存重开与实际导出。首次验证不改作者当前作品。
- **C 创作**：真实角色/插画的取舍、修订、正侧背一致性和表达，由作者判断。

当前代码中的超时、身份、像素格式、资源限制和非破坏保护继续适用。先解决实际任务的问题，再验证对应能力；不以增加记录、空组或通过测试代替视觉成果。

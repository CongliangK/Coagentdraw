# 第二阶段：AI 查找与获取参考图的能力分析

## 结论

本机已具备「查找候选 → 打开来源页 → 定位图片 → 获取公开大图 → 看图筛选」所需的工具。对博物馆公开藏品和 Wikimedia Commons，可以形成较稳定的获取路线；搜索引擎、艺术家平台与社媒不能承诺同样稳定。

**下载正确、视觉适用、历史归属准确，是三件不同的事。** AI 可自动处理获取和初筛；最终选择哪些图作为主参考，仍是设计判断。历史年代、文化归属和制作工艺应以来源记录为依据，而不是靠图像模型猜。

本报告只验证少量真实页面及工具能力，不重复另一 agent 的三图下载实测。

## 1. 本机当前工具情况

| 工具 | 本次确认 | 实际用途 |
|---|---|---|
| browser-use | 已加载并通过现有浏览器访问真实页面。`bu` 不在 PATH，现有入口是 `~/.agents/skills/browser-use/scripts/bu` | 搜索页面、渲染动态网页、读 DOM、定位图片与详情页 |
| proxy | `127.0.0.1:7890` 访问 Google 返回 HTTP 302，代理连通 | 海外 HTTP 获取使用显式代理；浏览器还需检查自身实际连通性 |
| HTTP 客户端 | 通过代理 HEAD Commons 原图返回 HTTP 200、image/jpeg、Content-Length 4605797 | 下载直链与核对响应；200 后仍需解码验证 |
| image-vision | GLM 直接读 Commons URL 报 1210；换官方 Cleveland 源图 URL识别成功 | 检查对象、可见部位、视角和参考用途；本地文件输入能避免云端远程抓图的额外不确定性 |

浏览器由多个 agent 共享，全局当前标签会相互干扰。本次出现过打开 Met 后读取到另一个标签的 Google 验证页。随后使用 `js(..., target_id=明确标签ID)` 提取目标页面。实际批量工作应明确标签 ID 或串行协调，不能依赖全局 current tab。

## 2. 少量真实页面证据

### A. 博物馆：Met 的盔甲藏品页

页面：[Armor Garniture of George Clifford，藏品 23939](https://www.metmuseum.org/zh/art/collection/search/23939)。

真实页面可读到：

- 藏品号 `32.130.6a–y`、制作者记录、地域英格兰格林威治、钢/黄金/皮革/织物材料。
- 标记 `Public Domain`，有 `Download Image` 与 `Enlarge Image` 控件，并链接 Open Access API。
- 可见视角标注 `3/4 right`。
- 当前主图自然宽度 939px；其他视角的图片标签使用 `loading=lazy`，部分 `currentSrc` 为空、自然宽度为 0。
- 相关推荐存在 225/480/575/600px 的 `srcset`。它们是不同用途的网页派生图，不应当全部作为目标藏品原图。
- 本次中文页面顶部出现 `1586`，详细信息又出现「约1585年」。因此应记录具体字段与原文，必要时核对英文详情/API，而非随手压成一个确定年份。

**说明**：原图获取入口和历史信息都较清楚，但必须将图片、视角、藏品号绑定。抓全部 `img.src` 很容易抓到相关推荐、缩略图或未加载的其他图。

### B. 公共图库：Commons 的搜索与文件详情

搜索页：[armor gauntlet 的 MediaSearch](https://commons.wikimedia.org/w/index.php?search=armor+gauntlet&title=Special:MediaSearch&type=image)，本次显示 2,150 个结果。搜索图多数是 250px 缩略图，可以从结果链接进入文件页。

已打开的文件页：[Gauntlet，Cleveland 藏品 1916.1901.b](https://commons.wikimedia.org/wiki/File:Unknown_artist_-_Gauntlet_-_1916.1901.b_-_Cleveland_Museum_of_Art.jpg)：

- 页面明确区分预览 `960 × 996` 和原文件 `3276 × 3400`，原文件约 4.39MB。
- `.fullMedia a` 给出 `Original file` 链接，`.fullImageLink img` 则仍是 960px 预览。
- 标明 CC0、Cleveland Museum of Art 来源及藏品号，链接[馆方藏品记录](https://clevelandart.org/art/1916.1901.b)。
- 文件历史记录给出[馆方源图](https://openaccess-cdn.clevelandart.org/1916.1901.b/1916.1901.b_print.jpg)。

本次还尝试了一个猜测的 Commons 文件名，页面明确显示文件不存在。这说明应从检索结果提取实际文件链接，不能编造文件名或根据藏品名猜 URL。

**说明**：Commons 的发现、原图定位和授权字段很适合自动化；但分类和文件名不是历史归属的最终证据，应沿来源链接核对。

### C. 艺术家平台与搜索引擎

[Jason Chan 的 ArtStation 页面](https://www.artstation.com/jasonchanart)本次出现「请完成安全检查以继续」，没有进入作品内容。

本次共享浏览器中的 Google 搜索出现异常流量确认页；百度也有安全验证标签。搜索引擎发现这一步本身就可能被打断，不能把「网络代理连通」当成「自动搜索一定可用」。

社媒本轮未独立实测。登录墙、无限滚动、短期签名 CDN、转发与压缩图是需要单独检验的机制，不将这些概括为某个具体社媒已发生的事实。

## 3. 搜索怎样更准确

以 **对象 + 部位 + 视角 + 用途** 组织问题，再转换成检索词：

| 维度 | 示例 | 价值 |
|---|---|---|
| 对象 | 护手、背篓、某职业服装；附文化/时代 | 限定实际设计对象 |
| 部位 | 手指关节、腕口、肩带连接、袖口 | 将「好看的图」变成能解决结构问题的图 |
| 视角 | 侧面、背面、内侧、展开、佩戴状态 | 提高目标结构确实可见的概率 |
| 用途 | 穿戴结构、动作参考、剪裁、材质细节 | 决定所需清晰度与图种 |

示例：研究护手腕部连接，可分两次检索：`gauntlet wrist detail museum`、`gauntlet side view articulation`。先发现来源，再在馆内或 Commons 检索，不必把所有词塞进同一次查询。

「用途」通常是内部筛选标准；`close-up / detail / back / worn / pattern` 等可视觉化词再加入搜索。抽象词「用于角色设计」往往没有「背面、连接、佩戴」有效。

## 4. 可执行的最短链路

1. **把调研问题转成图片任务**：写对象、必须可见部位、视角、用途；如需历史归属，加文化/年代。
2. **发现候选**：优先馆方检索或 Commons；通用搜索用于找来源页。搜索受阻就换公开来源，不反复消耗在验证码上。
3. **打开详情页**：读取名称、藏品号/作者、年代/地区、来源和图像使用条款；确认当前图与条目相对应。
4. **定位大图**：优先官方 Download/Original file/API/IIIF；检查当前图、`srcset`、懒加载和其他视角。选择实际公开提供的最大适用版本。
5. **下载并检查文件**：跟随重定向，必要时在允许的浏览器会话中下载；核对 MIME、解码后的尺寸、文件非空与画面内容。为文件保留来源页和图片 URL。
6. **视觉初筛并注释**：有原生视觉能力时直接看图，文本模型再使用 image-vision 检查部位/视角/清晰度；写「借鉴什么、解决什么问题」，交人选择主参考。

最短成果不是一个无说明图片目录，而是：**图片 + 来源页 + 对象/视角/用途注释**。

## 5. 原图与访问机制如何处理

| 情形 | 处理方式 |
|---|---|
| 搜索结果缩略图 | 只作发现，进入来源详情后取大图 |
| `srcset` / 响应式图 | 根据实际候选尺寸选择，不认为当前显示图即原图 |
| 懒加载 | 必要时滚动到目标区域、切换图库，确认真实 URL/加载状态；也可使用公开 API |
| Download 按钮由 JS 实现 | 检查按钮事件/网络请求或实际点击，不能只找 `<a>` 就宣称不存在下载 |
| HTTP 200 返回 HTML | 属于获取失败；用 MIME 和图像解码识别验证码/登录页伪装文件 |
| Referer / Cookie 依赖 | 在正常公开会话中请求，保留正确引用关系；不以无头 curl 失败推定无法下载 |
| 临时签名 URL | 从当前详情页重新取得，保存稳定来源页而不是只保存易过期直链 |
| 登录/付费/安全验证 | 当前自动链路停止，换公开候选或交人选择，不安装、登录或付费 |

## 6. 哪些能自动完成，哪些不能稳定承诺

| 类别 | 适合自动完成 | 需要人选择 | 不稳定部分 |
|---|---|---|---|
| 博物馆公开藏品 | 详情/图像定位、元数据整理、公开大图获取 | 是否适合作本角色主参考 | 有些藏品没有公开大图，多视角不齐，字段可能有归属保留或差异 |
| 公共图库 | 搜索、文件页、原图与授权字段获取 | 对构图/剪裁/气质的价值 | 误分类、描述不足、来源断链 |
| 艺术家官网/作品平台 | 可访问时提取作品、作者及大图 | 风格借鉴价值和主参考取舍 | 动态加载、安全验证、作品图非可自由复用 |
| 社媒 | 开放帖子可做候选收集 | 是否继续追溯原作者、接受何种清晰度 | 登录墙、压缩、转发、短期链接、自动化限制 |

## 7. 核验方法：三层分别确认

- **文件正确**：URL 对应目标，文件可解码，尺寸足够，图像不是整页截图、缩略图、图标或错误页。
- **视觉适用**：实际看得到指定部位、视角和结构；遮挡、清晰度与裁切是否满足用途。图像模型可辅助，但细致的工艺命名仍要来源证据。
- **历史归属**：查馆方/原作者记录，区分制作年代、收藏年代、拍摄年代；保留「约、可能、归属于」等原始措辞。照片显示某种结构，不等于已经证明它代表整个时代或文化。

另外单独记录图像条款：能够下载不等于能重新发布；作为内部参考与在成品/报告中复用图像是不同用途。

## 8. 最小验证建议

配合另一 agent 的三图测试，三张都记录同一组字段：调研问题、来源页、原图 URL、尺寸、对象、可见部位/视角、用途、来源依据。

至少覆盖「服装剪裁」「道具连接」「佩戴/动作」三类问题。对每张图同时检查文件正确和视觉适用；其中一张沿官方记录核对历史归属。记录失败发生在发现、页面、直链、下载还是看图环节。

三张成功可以证明链路能跑通；可据此先将第二阶段写成「AI 收集并注释候选图，人选择主参考」，不需要等到所有站点都可稳定抓取。

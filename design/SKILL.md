# Coagentdraw｜角色设计与插画创作

本目录本身就是技能包，既有规范与手册仍是唯一内容源；不另造一套八阶段流程。技能负责**触发、阅读路由、执行约束和交付前核对**，不代表绘画工具已经具备全部能力。安装见[技能包说明](<README.md>)。

## 1. 开始任务前：先加载，再执行

1. **明确这一次做什么。** 从作者当前指令识别对象、阶段、所选模板、交付物和不做的内容。已有角色就围绕该角色，不把“多个起点”曲解为必须另造多个人物；只做人物形象就不擅自扩成环境、事件插画或小说修订。
2. **必须实际读到正文。** 首次进入创作任务，依次读[正式执行规范](<Krita中枢创作流程_正式执行规范.md>)、[手册导航与共用规则](<执行手册/README.md>)、下方对应阶段手册。摘要、目录、上次会话的记忆不能替代正文；仅修改本技能的加载机制时，不必通读八本创作手册。
3. **作者提供的模板先读原件。** 附件、明确路径或点名文档是本次执行依据；先核对与仓库版本的区别。未经要求，不修改只读附件、不以仓库中的另一版静默替换它。
4. **按需补资料。** 先读与当前设计直接相关的资料；研究报告和工具命令按下表取用，不把整个目录一次塞进上下文。
5. **检查既有工作。** 仓库内任务先读仓库说明与协作规范，检查已有改动；从创作子目录启动也不能漏掉仓库根的指引。项目素材与成果留在作者指定项目内。

## 2. 填表就是交付约定，不用自由文章替代

- **有锚点就能进入试拼。** 沿用当前角色和已知条件，经02找角色与对应资料，再在04试拼大型；性别可选，不强迫补齐全部风格条件、先完成整卡或独立剪影。默认拼贴原型后重构线稿、再上色；这条试点仍待真实验证。
- **形状语言用于分析与调整。** 在试拼中观察圆、三角、方形等主形与辅形的方向、比例、分布和轮廓节奏，用身体、服装和装备形成可讨论的整身粗方案，与作者讨论构成取舍。完整意图卡也应提出具体方向，不要只提问、留白或罗列小配件；不把抽象几何讨论作为找图的前置。情绪倾向结合宽窄、重心、曲直与语境判断。
- **按结构依赖细化。** 整身剪影与主体构成 → 依附结构 → 表面细节。主体推翻后重新判断依附设计；剪影是轮廓检查手段，原型转线稿时须重新解决连接、厚度、遮挡与细节，不能以描边代替设计。
- **视觉重心写核心识别组合。** 本卡的“视觉重心”记录共同定义角色的具体视觉要素及其关系，例如服装大形、身体比例、关键装备、发廓与主色块；多项核心要素可以协同承载同一核心命题，不限定为唯一部位或单个物件。写出可直接画出的类别、形状、长短、体量和色块关系；“脸部是重点”“好奇的眼睛”“熟练的手势”或笼统的“降低对比”不能替代核心造型方案。画面视线落点属于呈现设计，神态与小动作在对应细项内处理。
- **保留所选模板的标题、栏目、字段及填写提示。** 普通表填“填写内容”，外观表分开填“已有条件”和“初步探索方向”。先写整体剪影及主体构成，再在各层按视觉主次组织。作者明确要求重构模板时，同步更新指引。
- **简洁是单元格写短，不是把表裁掉。** 默认每格一两句；背景只保留影响本次形象的部分。作者要求集中记录一次，其他格直接落实，不换词重复；不附加表格或人物长文。
- **核心幻想是角色设计的中心。** 保留“核心幻想”字段，回答角色为观众、玩家或读者提供怎样的幻想与想象；人物特质与可见形象承载这一幻想。
- **意图卡只保留两部分。** 按“作者要求与设计锚点—可见形象”填写，作者约束统一放在“作者要求”中，不另加表单。来源在对应已有条件格内短链接。作者指定附件时遵从所选结构。
- **填写提示简短直问。** 角色标识只问名字或代号；设计目的只问用在什么上面、要起到什么效果；核心幻想直接问幻想与想象；表现风格用专业风格名称举例。模板提示采用正向描述，删除防御性尾注。
- **外观不能全部推迟。** 完整卡需要触及时间锚点、身体面貌、发型、剪影形状、服装、武器/媒介、工具配饰、配色、材质、纹样和神态姿态。武器或装饰可明确无，不为凑齐强加；现有事实放已有条件，受委托设计时提出具体且标为未定稿的探索方向，不把没有既定外观误解为不许设计。
- **未知与建议分开。** 保留字段，注明暂无/不适用或具体缺口，不捏造人物硬设定。提议不是作者已确认的条件；不能整张外观表只写“待确认”或“体现某性格”，也不把几何形状机械等同于人格。已有资料由助手提炼，不让作者重抄。
- **完整卡粗定整体，当前锚点可先试。** 主导剪影与核心构成应形成可讨论、可想象的粗方案；可以由检索和试拼补出具体方向，允许反馈后推翻或重构。粗定方向与最终锁定分开，不追加审批链，也不让作者为起步重填全部资料。

## 3. 作者反馈怎样落实

- “核心是某种反差／情绪／幻想”是在校准表达重点，不自动授权删除其他字段，也不是把所有格子重复成同一句话。
- “写得太多”优先删除模板外扩写、缩短格内文字；不能从一篇长文直接跳到漏项口号。
- “只做角色／不要环境”是本轮范围：只保留直接影响人物形象的必要背景，不写环境设计、场景构图或情节提案。不把这条项目选择变成所有未来作品的永久禁令。
- “按这个做”先检查是否实际遵循文档结构和交付物，而不只是声称理解理念。遇到偏差先修正对应内容，不靠新版本数量、更多解释或状态记录证明认真。
- 作者指出执行偏差时，区分助手执行失误、加载入口缺失、规则歧义和真实工具限制；没有技术阻碍就不虚构阻碍。需要改流程时将通用规则写入技能或手册，不公开私有作品细节。

## 4. 角色设计、画面制作和工具工作分开

1. **当前阶段优先。** 角色阶段不提前设计事件插画，插画表达也不反过来擅改已确认角色。允许按作者要求回退，不自行增加宏观阶段或审批链。
2. **事实与建议分清。** 已确认条件、资料记载和助手新提议分开；建议不自称作者已认可。不把抽象主题强配成饰品，也不把所有成长经历塞进一套衣服。
3. **视觉成果回到 Krita。** 草图、当前绘制/编辑结果和本轮素材优先放在同一工作画布，素材旁置便于对照与拼贴；保留独立层，输出时隔离参考。 阶段一允许纯文本；后续所需想象板、探索稿、实际改图、三视图和插画不能用 Markdown、JSON、空图层或工具调用代替。
4. **默认非破坏。** 新结果先候选，保留原稿、旧分支及可编辑源；覆盖、删除、合并、上传私有素材须有相应授权。模型执行、作者选中、实际采用与阶段批准不是同一件事。
5. **工具只为具体问题服务。** 不为填表前置安装、重启、生成、Blender 或新控制管线；无实际需要不登记一堆机器事件。不用自写项目 JSON 绕过现有版本守卫，批准必须有真实人类来源。

## 5. 交付前自行核对（不另让作者填检查表）

- 本次选用的模板和阶段手册是否真的读过？字段与提示是否完整，外观是否先整体后局部、各层按视觉主次组织？
- 是否围绕当前锚点试验，而非被整卡、独立剪影或抽象几何前置阻断？是否用主形与辅形分析整身粗方案的构成取舍，依附细节是否建立在主体选择之上？
- “视觉重心”是否写出了共同定义角色的具体服装、身体大形、装备、发廓与色块组合，以及它们的构成关系？仅凭文字能否画出这些主要构件？
- 作者最新校准的表达重点是否被准确采用？填写提示是否简短直接？
- 完整卡是否有时间/身份锚点和具体的可见形象方向，尤其服装、武器/媒介（可无）、形状与配色？只填满背景不算外观设计。
- 是否有作者没有要求的长文、环境、场景、剧情或后续阶段内容？删去无必要部分。
- 未知项是否诚实标明，资料记载和新建议是否分列，而非把提议写成已定事实？
- 声称完成的成果是否真实存在，作者批准与否是否准确？少量文字修订是否被不必要地变成了大量文件或索引操作？

**执行顺序：读所选模板 → 读当前阶段规则 → 在原结构内完成本轮内容 → 按作者范围自检 → 简短交付。**

## 6. 路径与加载失败处理

本页相对链接从技能目录解析，八阶段手册仍在本包中。软链接安装后，不假定智能体当前工作目录就是工具仓库；需要访问仓库级工具或协作规范时，先解析本页真实路径，再取其父目录作为仓库根，不把技能挂载目录的父目录误认为源码根。

技能未出现在当前会话目录、调用失败或正文未加载时，直接读取仓库的本页与对应手册继续；说明加载边界，不把目录存在说成技能已成功调用。新增技能能否热发现由宿主决定，必要时重新扫描技能或开启新会话；不要为此擅自重启服务。

# 阶段8｜插画制作与交付

> 现行手册；稳定 ID：`illustration_production`。工具能力见[能力说明](<../工具能力与验证.md>)；共用规则见[手册导航](<README.md>)。

沿阶段七的结构与光色确认稿，在同一 Krita 插画文档中持续制作。8A—8G 保留为制作内容与检查角度，日常合为下面四轮；可以往返，不新增阶段、审批链或逐轮表单。

| 项目 | 填写提示 | 填写内容 |
|---|---|---|
| 8A 制作准备 | 第一轮：保存确认稿与可恢复 KRA；核对既定画幅、当前基底、角色依据和保持关系，分开参考、制作与候选 | |
| 8B 整体成形 | 第一轮：把角色、道具和环境的形体、基础色、明暗一起建立；同尺度对照确认稿，保住镜头、动作、身份与焦点，余下问题能定位 | |
| 8C 关键结构与焦点完成 | 第二轮：从当前主稿选最影响表达的问题，连同相关部件、接触与过渡一起修；候选经局部和全图比较、作者接受后才成为新基底 | |
| 8D 材质与细节 | 第二轮：先体积与接触，再材料主要反光、褶皱和边缘，最后按需要补纹理；重点可细，次要区域保留概括 | |
| 8E 全图统一 | 第三轮：指出抢焦点、拼接、边缘或光照冲突，用下表具体操作修正；每次回全图复看，不以一次全图重生成代替诊断 | |
| 8F 尺寸与收尾 | 第四轮：按既定用途、像素尺寸与比例准备输出；需要放大才在副本上处理，保留放大前版本并复检新增问题 | |
| 8G 验收与导出 | 第四轮：实际重开 KRA、检查起作用的编辑层及最终导出图；交付最终 PNG、有效可编辑 KRA、已有角色设定版本引用与交付清单 | |

## 第一轮｜建立整幅底画（8A＋8B）

先保留阶段七确认稿，核对其画幅与裁切、人物大小和位置、动作与接触、遮挡、焦点、明暗大块、主光和冷暖关系。角色、主要道具和环境一起进入底画；背景可以简洁，但色块、空间和对比要已参与构图，不能等人物精修完才临时补背景。

沿用现有[插画组层](<../../core/cwb_workflow.py>)：`00_角色参考与画面意图`、`10_构图候选`、`20_确认稿`、`30_制作`、`40_AI修改候选`、`90_诊断与比较`。制作组已有结构与底画、光影、关键区域、材质细节、全图调整；按实际修改需要保留基础色、结构依据、补绘或蒙版，不以空组或层数证明完成。

普通双参考 [edit](<../../comfyui/wf_qwen21_edit_api.contract.json>) 可用“场景草稿＋角色设定”尝试整体底画候选。请求明确沿用当前镜头、位置、动作、遮挡和光色；这是参考驱动的生成，**不是几何锁定**，不能保证照搬确认关系。参考必须实际进入输入，不能因为画布外放着参考就声称模型看过。

候选与确认稿按同尺度比较，先看镜头和人物比例、动作与遮挡、角色身份、焦点与明暗大块，再看细节。关系成立且只剩可定位问题，可以继续；镜头、主要动作或整套身份改变，就拒绝，或在作者有意转向时保留为新方案分支。相同关系反复漂移时，先补清轮廓、接触、遮挡、光色或拼贴/结构依据，再尝试；输入与办法没有变化，不靠更多全图生成次数解决。

保留作者原始源稿和确认快照，当前工作版本连续演进；不擅自改变源 KRA 的既定画布尺寸。缩小只用于查看或小稿/比较副本，不缩小源文件；输出另存，覆盖作品、删层或合层仍须授权。底画完成的依据是整幅表达已成立，余下问题能指出“在哪里、是什么”。

## 第二轮｜按问题修相关局部，再补必要细节（8C＋8D）

从当前主稿找最妨碍表达或角色成立的一处：可能是表情、视线、道具方向、背影轮廓，也可能是人与环境的尺度；不固定“脸和手先做”。先说明哪里没有接上、哪条轮廓妨碍动作读取、哪块亮部抢走焦点，以及希望怎样改变。作者只能感到“不对”时，可以先做小范围对比或示意，不要求先说出专业术语。

一次解决一个主要问题，范围按关联关系划定，**可以跨多个部件或原先划分的区域**。例如持握涉及手、手腕、握柄和接触阴影，不能机械拆开分别生成。结构成立后，再按“大体积与接触 → 材料主要反光、褶皱和边缘 → 必要微纹理”推进。焦点和身份特征获得必要信息，次要区域保持概括；厚涂、清线加色或偏平面画风均可。

[HQ局部编辑交互工作流](<../../comfyui/interactive/README.md>) 使用**当前底画＋手绘真实蒙版**，在 ComfyUI 界面运行。图像条件与VAE编码共用裁切底图，蒙版用于噪声约束和像素拼回；没有额外独立的三视图、Pose或Depth输入，也不把蒙版当作第二张角色参考图。因此底图须先承载正确身份，红圈诊断不能冒充有效蒙版。当前模板外扩16像素、融合32像素，须复看邻域；原始白区不是最终影响边界。该模板尚无真实生成与艺术验收，不能保证蒙版内画对；CLI仅支持普通参考图编辑。

每次先输出独立候选，比较问题是否改善，再回全图检查身份、动作、光线和焦点；作者接受须对应实际候选与源版本，实际采用后，下一轮只从这个当前版本继续。不能把互相影响的部件并行修在旧底画上，再假定补丁可自然拼合。无有效蒙版、身份或坐标映射、源版本已变时，只保留独立候选，不自动回填；无选区不默认整图，超时未知先查结果，不盲重试。

每次 AI 画改只需下面这一条短任务，仍用现有一体表。输入/输出位置、文档/层/区域、源版本与运行参数尽量由工具记录；表内可引用已有记录，不另造表单，也不凭空指定实际作品的问题。

| 项目 | 填写提示 | 填写内容 |
|---|---|---|
| 当前稿 | 本轮实际使用的插画版本与确认稿 | |
| 本轮问题 | 看见什么，为什么妨碍表达或角色成立？ | |
| 目标变化 | 希望哪里发生怎样可见的改变？ | |
| 相关范围 | 哪些部件、接触和过渡需要一起处理？ | |
| 保持关系 | 特别要保住的镜头、动作、身份或光色 | |
| 比较结论 | 改善了什么，是否接受，下一处改什么？ | |

调用完成、得到输出、导入 Krita、作者接受、实际采用是不同事件。[compare](<../../docs/tools/compare.md>) 可辅助比较与决定记录，接受记录不会自动替换主稿；[review](<../../docs/tools/review.md>) 尚无已验证的实际审评后端，不能充当自动美术总监或替作者批准。

## 第三轮｜把全图统一落到具体操作（8E）

先缩小看，选最明显的竞争关系或拼接问题。下表“GUI”由作者在 Krita 界面执行，或由具备相应界面操作能力且获授权的助手执行；当前[插件路由](<../../core/krita_cowork/server.py>) 没有通用笔刷、变形、滤镜接口，不能把这些动作写成 CLI 已自动支持。

| 观察到的问题 | Krita 具体操作 | 执行方式 | 全图复看 |
|---|---|---|---|
| 背景某处比主题抢眼 | 在独立调整/绘制层中选出该处，降低亮度、饱和度或局部对比 | GUI | 第一眼是否回到预期焦点？ |
| 新修区域像贴上去 | 用透明蒙版保留可恢复的取舍；另层调整明暗、冷暖、边缘并补接触关系 | GUI | 是否属于同一空间与光照，轮廓是否仍成立？ |
| 所有轮廓一样硬 | 保留焦点必要硬边，在独立修订层适度柔化或弱化次要轮廓 | GUI | 主体是否清楚，边缘有无主次？ |
| 材料都一样碎、一样亮 | 减少非重点纹理，合并零碎明暗，保留材料主要反光和形体区别 | GUI | 细节是否帮助辨认，是否抢走焦点？ |
| 人物、道具和环境光线矛盾 | 对照主光与遮挡，在光影/补绘层修正受光面和阴影 | GUI | 三者是否能处在同一光照与空间中？ |

透明蒙版保留被隐藏像素，适合可恢复合成，但不能自动消除镜头、动作、透视或身份冲突；不要扩大羽化来掩盖关系错误。某项融合超出当前 AI 与二维操作能力时，明确记录瓶颈，补局部参考或结构依据，或由作者决定简化呈现；不能留一句“资深画师最后润色”当作已解决，也不要求作者突然具备资深厚涂能力。

## 第四轮｜按用途收尾与交付（8F＋8G）

依次看三个尺度：缩小看主次、表达与观看顺序；实际展示尺寸看身份、动作、表情和关键材料；重要局部看结构错误、合成边缘与残留。仅在目标用途确实需要时放大输出副本，复看新增纹理、五官、装备符号和边缘；不强制超分，不用放大修结构。

**可编辑性检查：** 角色设定源继续保留正侧背的线稿和基础色，新镜头则必须有当前姿态的结构依据、基础色与修订层。需要分别调整的结构、色块、光影或关键部位，应有真实起作用的层或蒙版。把旧线稿与平涂留在底下，再盖一张不透明 AI 成图，不算最终画面具有这些独立编辑能力；AI PNG 仍是合成位图，不会因为放进 KRA 就恢复线稿、平涂和光照。接受候选后按实际需要分区、建蒙版、保留补绘与调整层，检查调整是否确实作用于目标内容；这些操作只恢复具体内容的可改性，不保证自动语义拆层。可保留粗结构线用于修改，画风不需要时不强制终稿清线。

保存有效可编辑 KRA 并**实际重开**，核对层、可见性和编辑作用；再打开**实际导出图**，检查像素尺寸、比例、色彩、裁切、透明度和导出范围，没有参考、红圈或诊断污染。未重开或未看实际输出就标为待检查，文档静态检查和离线测试不能替代这一步。角色设定用已有版本引用交接，不复制新设计档案；最终图、KRA、设定引用与交付清单相互对应。

## 按问题回退，不重走全流程

| 实际问题 | 回到哪里及下一步 |
|---|---|
| 情绪、状态或事件没有被读到 | [07 表达与构图](<07_插画方案探索.md>)：重新比较镜头、动作、遮挡或光色 |
| 主要动作、支撑、透视不成立 | 07 当前镜头的结构依据：先解决关联结构，再继续细化 |
| AI 改脸、改装备或改身份 | 当前插画修订：对照已确认设定纠正，不自动回 05/06 重设计 |
| 单处接触、轮廓或材质不对 | 08 局部制作：修这组相关关系 |
| 越画越乱、局部割裂 | 08 全图统一：削弱竞争信息，重组边缘与光色 |
| 出现值得采用的新大方向 | 保留旧稿，返回 07 新分支比较，由作者决定是否转向 |
| 只有目标尺度的清晰度不足 | 08 尺寸收尾：处理必要尺寸问题并复看 |

只有已确认的角色设计自身确有矛盾，才回 05/06 修正，并复看受影响插画。生成结果漂移不等于原设计需要重做。

**完成与交接：** 核心表达、角色身份、观看效果与交付规格成立，主要问题已解决，作者认为继续修改没有明确收益时停止，不用模型自评分或装饰量判断。真实读者若参与，先请其自由描述第一眼看见什么、人物状态和感受，再对照意图；作者自检、AI 诊断不能记成已完成外部读图验证。没有实际作品就记未完成，流程文档不冒充制作证据。

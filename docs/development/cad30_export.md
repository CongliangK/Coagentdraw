# CAD-30：最小确定性本地成果导出

## 验收边界

这是阶段 A 的**阶段四 fixture 最小包能力**，不是完整真实作品验收，也不代表 Issue #30 的全部作品交付完成。真实 `.kra` 保存/重开、最终图像的视觉质量、完整八阶段角色设计与插画均未验证。本命令不调用 Krita、ComfyUI、模型或网络，不上传、发布或修改项目。

只读消费schema 2项目状态和资产索引，保留workflow、多起点/文档/决定及资产对象版本/身份。仅显式选择final资产，final不等于人类批准；不自动生成角色设定或插画。CAD-10 已保存的工作流如需交付，先由使用者把**审阅过的必要工作流文件**登记为项目内 final 资产，再显式选择。不会递归消费 ComfyUI 运行目录、缓存或外部依赖。

## 使用

先通过现有 `project status` 查看资产 UUID。必须逐项 `--asset UUID`，没有“全部打包”选项。只接受已登记的 `category=final`，不因文件名或所在阶段自动判定正式成果或交付用途。

```bash
python3 core/cwb.py export-project /绝对/项目目录 /绝对/交付目录 \
  --asset <PNG资产UUID> --role final_png=<PNG资产UUID> \
  --asset <KRA资产UUID> --role kra=<KRA资产UUID> \
  --asset <工作流资产UUID> --role workflow=<工作流资产UUID> \
  --metadata export_notes.json

# 同样选择，直接输出本地 ZIP；不同时生成交付目录
python3 core/cwb.py export-project /绝对/项目目录 /绝对/交付.zip \
  --asset <PNG资产UUID> --role final_png=<PNG资产UUID> --zip
```

输出必须不存在，父目录须事先存在；不覆盖现有文件、目录（包括空目录）或悬空符号链接。不能输出到项目内，也不能把项目的祖先目录作为输出。

`--role ROLE=UUID` 仅引用本次显式选中的资产；支持 `kra`、`final_png`、`setting`（主要设定图）、`workflow`、`design_description`、`reference_sources`、`version_record`。可对多个工作流或设定图重复指定同一用途，但不能重复同一映射。用途是用户声明，不验证文件格式，更不证明 KRA 可打开、作品已完成或参考素材具有授权。没有声明的用途保守列为缺失，即使存在相同扩展名。

既有状态不能表达的设计说明、必要来源、主要作品版本记录，用项目内显式 sidecar 补充：

```json
{
  "description": "当前阶段四探索稿的设计说明；仍未完成最终插画。",
  "references": ["作者、来源网址、用途及授权限制；未知时写明未知"],
  "versions": ["v1：手工剪影探索；v2：调整轮廓"]
}
```

三个字段均可省略；只允许这些键和示例中的类型。命令不猜测意图卡字符串是不是文件路径，不自动读取其中提及的文件，也不跟随来源链接下载原图。sidecar 是显式选入的元数据，应先人工检查，不包含凭据。

合法且未变化的同一个文件可同时作为 sidecar 和显式选中的 final 成果：包内 `export_metadata.json` 与 `assets/<该文件相对路径>` 保留相同字节；目录和 ZIP 契约一致。同一资产也可声明多个不同用途，但同一映射不能重复。源状态不符合 sidecar 字段契约，不能直接用作 sidecar；状态与锁文件仍由 CAD-19 的既有 schema 禁止登记为成果。

## 包内内容与缺失清单

- `project_state.json`：源状态字节快照，包含现有意图、支柱、风格锚点、阶段状态、索引与阶段历史。**索引提及某资产不等于该资产已复制。**
- `assets/<原项目相对路径>`：仅显式选定 final 成果，路径结构不变。
- `export_metadata.json`：若指定 sidecar，保留其原字节。
- `design_notes.json`：可读 JSON 设计说明与现有元数据；阶段历史保留但不冒充作品版本记录。
- `README.md`：可直接阅读的简要说明、验收边界与缺失项。
- `export_manifest.json`：选入成果及用途、SHA-256、大小、阶段；所有其他包内文件的 SHA-256/大小；缺失用途、意图卡、支柱及源文件。清单不自包含自身哈希。

命令标准输出也是 JSON 清单。缺项允许阶段四导出成功，但必须查看 `missing` 与 `missing_assets`；已选资产若起初不存在，不复制并明确列缺失。如果存在但 hash/size 与登记不符，或读取/导出期间源状态、sidecar、成果发生变化，则失败，不静默导出最新版本、不更新登记 hash。需要使用者自行确认新版本后通过既有项目命令登记。

## 确定性与安全

相同源状态字节、sidecar、明确选集及用途会生成相同的包内内容；不注入当前时间、输出路径或绝对源路径。文件与清单排序固定，ZIP 使用固定时间及权限、无压缩，以消除压缩器版本差异；相同输入的 ZIP 字节一致。源状态里已有的时间与 UUID 原样保存，不承诺不同项目初始化产生同一包。

路径拒绝绝对路径、`..`、`.`、空组件、反斜杠、驱动器及 NUL；源文件逐级用 `openat`/`O_NOFOLLOW` 打开，拒绝普通文件以外的对象，包括 FIFO；拒绝符号链接源/状态/sidecar/输出及父路径。拒绝重复 UUID、同一源路径的多个版本同时输出，以及文件/目录祖先冲突。

每个成果复制时验证登记 SHA-256/大小并重新核对副本；状态、sidecar、成果共用按安全相对路径登记的**首次读取快照**。同路径被另一角色再次读取时立即与首次快照比较，绝不以后读覆盖先读；发布前再次重读全部这些路径并与首次快照比较。比较涵盖 SHA-256、大小、设备/inode、mtime/ctime，因此即使恢复成登记版本或同字节重写，也不能掩盖已观察到的中途变化。不同路径的硬链接分别保留各自首次快照并重读，不按 inode 合并而漏掉路径替换。没有源写入、锁创建、目录扫描式源资产收集或自动打包原参考/暂存/缓存/凭据的逻辑。选择依据是使用者明确的 final 登记与 UUID，程序不能判断一个被人为错误登记的文件是否含秘密，选入前必须人工审阅。

在输出父目录建立私有暂存目录，失败清理仅该暂存目录；输出前不暴露半成品。目录用 Linux `renameat2(RENAME_NOREPLACE)` 原子发布（不支持则安全失败），ZIP 用不可覆盖的 hard-link 发布，并发新建目标也不会被替换。要求可信且导出期间不被重命名/替换的输出父目录和项目祖先目录；本版本不是面向敌对共享目录的沙箱，也不提供文件系统快照或断电持久化保证。发布前最后校验后仍存在不可完全消除的源并发写入窗口，因此应在停止编辑的项目上导出。

## 离线回归

专属测试覆盖阶段四最小包、元数据与用途、未选资产排除、源不变、包内 hash、确定性 ZIP、缺失、登记 hash 损坏、用户改图、输出已有目标、路径穿越、各级符号链接、FIFO、输出嵌套、重复/嵌套目标、sidecar 类型与路径、写出失败清理、导出期间改动、并发目标出现、CLI 帮助离线无业务缓存。快照别名回归同时覆盖目录/ZIP：sidecar 兼任 final 时 A→登记 B、同字节重写、状态→sidecar 两次读取间变化均拒绝；未选 sidecar 与硬链接别名变化仍拒绝；静态同文件/硬链接 sidecar 与 final、多用途共享字节成功，状态/锁成果与状态 sidecar 的既有拒绝边界不变。失败场景核对无输出、无暂存残留，源只保留测试注入的编辑、不被导出写回。
